# 🧠 Second Brain: Major Functionality Improvements & Implementation Plan

This document outlines major functionality improvements for the single-user Second Brain system, alongside a highly detailed, step-by-step technical implementation plan for each feature.

---

## 1. New Lacking Features (Prioritized)

### 1.1. Upcoming Events Widget & Content Suggestions
**Concept:** Automatically extract dates and event information from ingested content (like concert announcements, webinars, or reservation details) and display them in a dedicated UI widget on the dashboard. Additionally, provide intelligent "content suggestions" based on the user's current context or upcoming schedule.

**Detailed Implementation Plan:**
*   **Backend (FastAPI & AI Processing):**
    *   **Prompt Engineering (`core/processors.py`):** Update the Gemini 2.5 Flash Lite prompt during the "AI Synthesis" step. Instruct the model to strictly extract temporal data (dates, times, locations) and output a standardized JSON block in the frontmatter of the Markdown file (e.g., `event_date: 2024-06-15T19:00:00Z`).
    *   **Index Updates (`core/processors.py`):** When updating `metadata.json` or ChromaDB, parse the `event_date` from the frontmatter. Add a background task to maintain a separate `events_index.json` or SQLite table specifically for querying future dates.
    *   **New API Endpoints (`main.py`):**
        *   `GET /api/events/upcoming`: Queries the index for events where `event_date >= current_date`, sorted chronologically.
        *   `GET /api/suggestions`: Uses the current date and recent chat context to query ChromaDB for related nodes (e.g., if an event is coming up, suggest related notes or recipes).
*   **Frontend (React/Vite):**
    *   **Component (`src/components/EventsWidget.tsx`):** Create a dashboard widget that fetches from `GET /api/events/upcoming`. Display events in a clean timeline or calendar card view.
    *   **Component (`src/components/SuggestionsPanel.tsx`):** A sidebar or bottom panel that fetches from `GET /api/suggestions` to show "You might want to review: [Note Title]" cards.

### 1.2. Chat History & Previous Queries Access
**Concept:** Allow users to easily access the results of previous queries directly in the application via a sidebar, rather than losing context when refreshing the page.

**Detailed Implementation Plan:**
*   **Backend (FastAPI & Storage):**
    *   **Database:** Create a local SQLite database (`chat_history.db`) using SQLAlchemy or a simple `chat_history.json` file.
    *   **Data Structure:** Store `session_id`, `timestamp`, `user_query`, `ai_response`, and `sources_cited`.
    *   **API Endpoints (`main.py`):**
        *   `GET /api/chats`: Retrieve a list of historical chat sessions (metadata only).
        *   `GET /api/chats/{session_id}`: Retrieve the full conversation for a specific session.
        *   `POST /api/chats`: Save a new message/response pair to a session.
*   **Frontend (React/Vite):**
    *   **State Management:** Update the global state (e.g., Zustand or React Context) to manage the `currentSessionId`.
    *   **UI Component (`src/components/ChatSidebar.tsx`):** Build a sidebar listing previous chats grouped by "Today", "Previous 7 Days", etc.
    *   **Integration:** Modify the existing chat interface (`App.tsx` or `Chat.tsx`) to push new queries to the backend and load selected historical sessions from the sidebar.

### 1.3. Automated Folder Structuring
**Concept:** Currently, notes are saved directly into the vault. This feature will automatically organize notes into specific subfolders inside the Obsidian vault based on their category or filename.

**Detailed Implementation Plan:**
*   **Backend (File I/O):**
    *   **Refactoring (`core/processors.py`):** During the "Indexing/Physical" step, parse the category generated by Gemini (e.g., `Recipe`, `Event`, `Tech`).
    *   **Path Generation:** Construct the file path dynamically. Instead of `os.path.join(vault_path, filename)`, use `os.path.join(vault_path, category_name, filename)`.
    *   **Directory Management:** Add an `os.makedirs(os.path.join(vault_path, category_name), exist_ok=True)` check before writing the `.md` file to ensure the folder exists.
    *   **Update DBs:** Ensure the file paths stored in `metadata.json` and ChromaDB reflect the new nested directory structure.

## 2. Expanded Ingestion Sources

**Concept:** Move beyond social media video URLs to support text-heavy sources.
*   **Web Articles & Blogs:** Extract main text body, title, and author.
*   **Twitter/X Threads:** Extract tweet chains as single coherent documents.
*   **PDFs & Local Files:** Allow drag-and-drop of local documents.

**Detailed Implementation Plan:**
*   **Web Articles:**
    *   Add `newspaper3k` or `beautifulsoup4` + `requests` to `requirements.txt`.
    *   Create a new processor in `core/processors.py` that detects non-video URLs, fetches the HTML, extracts the article body, and sends it to Gemini for summarization and tag extraction.
*   **Twitter/X:**
    *   Integrate a tool like `twscrape` or use an API (if available) to fetch threads. Flatten the thread into a continuous text block before passing to the AI pipeline.
*   **PDFs/Local Files:**
    *   Add an upload endpoint `POST /api/upload` in `main.py`.
    *   Use `PyMuPDF` (`fitz`) to extract text from uploaded PDFs.
    *   In the React frontend, add a Drag-and-Drop zone using `react-dropzone`.

## 3. AI & LLM Enhancements

**Concept:** Deepen the "Second Brain" intelligence by moving beyond simple categorization to active knowledge linking.
*   **Semantic Auto-Linking:** AI automatically generates Obsidian wiki-links (`[[Note Title]]`) connecting new notes to existing ones.
*   **Graph/Concept Extraction:** Extract "Entities" (People, Companies, Tools) to create highly interconnected tags.

**Detailed Implementation Plan:**
*   **Vector Search Pre-Processing:** Before sending the transcript to Gemini, run a quick query against ChromaDB using the raw transcript to find the top 5 most similar existing notes.
*   **Prompt Injection:** Inject the titles of these 5 related notes into the Gemini prompt: *"Here are existing notes in the vault: [List]. If the new content relates to these, insert Obsidian wiki-links (e.g., [[Title]]) in the markdown output."*
*   **Local LLM Fallback:** Implement an `Ollama` client integration in `core/processors.py`. If the system is offline or the user wants total privacy, route the synthesis task to a local model (e.g., `llama3` or `mistral`) instead of the Gemini API.

## 4. UI / UX Features

**Concept:** Make the Mission Control dashboard more interactive and powerful.
*   **Vault Graph Visualization:** Implement a visual node graph of how notes connect.
*   **Interactive Tag Manager:** A UI to rename, merge, or delete tags across the entire vault.

**Detailed Implementation Plan:**
*   **Graph Visualization:**
    *   Add a new endpoint `GET /api/graph` that parses all markdown files in the vault, extracting `[[wiki-links]]` to build a nodes/edges JSON structure.
    *   Use `react-force-graph` in the frontend to render the web of connections.
*   **Tag Manager:**
    *   Create `GET /api/tags` to read `tags.txt` and `metadata.json` to get tag frequencies.
    *   Create `PUT /api/tags/rename` which runs a search-and-replace operation across all `.md` files in the `vault/` directory and updates `tags.txt`.

## 5. Backend & Performance Improvements

**Concept:** Improve system reliability, especially for high-volume ingestion or long-running audio transcriptions.
*   **Robust Task Queuing:** Move away from simple `BackgroundTasks` to a resilient queue that survives server restarts.
*   **Optimized Vector Storage:** Better chunking strategies for ChromaDB.

**Detailed Implementation Plan:**
*   **Task Queuing (Celery + SQLite/Redis):**
    *   Install `celery`. Configure it to use a local file-based broker (like SQLite via SQLAlchemy) to maintain the single-user local focus.
    *   Refactor `main.py` ingestion routes to dispatch Celery tasks. This allows the user to queue 20 URLs at once without blocking the FastAPI event loop or crashing if the server restarts.
*   **Semantic Chunking for RAG:**
    *   Update the chunking logic in `core/processors.py` (which currently splits for ChromaDB). Instead of fixed character limits, use a semantic text splitter (like `RecursiveCharacterTextSplitter` from LangChain) to ensure chunks don't cut off mid-sentence, vastly improving RAG chat accuracy.
